# KOMAROVA_CORE — Telegram family perimeter and integration model

**Document status:** architecture specification, 23 November 2026  
**Target branch:** `core-backend-foundation`  
**Implementation status:** four Telegram sources are registered in this architecture specification; no Telegram connector, browser automation, message sync or media import is implemented.

## 1. Purpose

Telegram is an existing family communication and publishing perimeter used for trips, city walks, family photographs, memories, and everyday conversation. KOMAROVA_CORE must be able to reference this perimeter without replacing it or requiring the existing bots to be rewritten.

Telegram remains an independent tool. The family website and KOMAROVA_CORE are separate systems with controlled, optional connections.

## 3. Non-negotiable compatibility rules

1. Do not rewrite, replace, migrate, or alter the source code of either existing Telegram bot as part of the website integration.
2. Do not change bot commands, handlers, hosting, deployment, webhook/polling mode, or permissions without a separate explicit approval.
3. Do not assume access to the bots' GitHub repositories merely because their public Telegram usernames are known.
4. The website must link to the existing bots using their canonical HTTPS Telegram links.
5. Telegram outages must not make the family website or KOMAROVA_CORE unavailable.
6. Telegram is not the authoritative family archive, identity registry, or permanent binary storage.
7. Never store bot tokens, API credentials, session strings, or private invite secrets in Git, public site files, frontend code, or ordinary documentation.
8. Do not create an automatic public bridge from Telegram messages to the public website.

## 5. Relationship to KOMAROVA_CORE

Telegram is an external source/channel, not a replacement for the core registry.

The target relationship is:

- Two Telegram bots: existing family bot interactions; preserve their behavior.
- Family group: shared family conversation and selected media.
- Daughter's personal Telegram account: a separate private source, accessible only through her own authorization and only for content she explicitly permits.
- Son's personal Telegram account: a separate private source, with age-appropriate consent and guardian oversight; import only content explicitly approved for the family archive.
- Mother's Telegram source: a private chat/group locator whose exact peer type and identity must be verified before access or import.
- KOMAROVA_CORE: authoritative people, events, places, media metadata, permanent IDs, provenance, and permissions.
- Family website: a curated presentation surface for explicitly approved material.

A Telegram account, username, message ID, chat ID, or file ID must never be used as a PERSON-ID, PHOTO-ID, ArchiveItem ID, or event ID.

If Telegram references are later imported, preserve their source identifiers as provenance fields under a connector/source record. Do not make external Telegram identifiers the primary identity of family entities.

## 6. Media selection and import policy

The owner explicitly stated that the family group contains many routine, unsuitable, or low-quality photographs and that not all content is intended for the website.

Therefore:

1. **No bulk download now.** Do not download, mirror, scrape, or import photographs or videos from the group at this stage.
2. **No automatic media ingestion.** A Telegram post or uploaded image does not automatically become an archive item.
3. **Manual selection first.** Only items explicitly selected by an authorized family user may enter the future archive intake workflow.
4. **Separate archive and publication decisions.** A selected item may be preserved privately without being published.
5. **Preserve originals.** If a selected file is later imported, retain exact original bytes, checksum, source provenance, and a separate preview/derivative.
6. **Duplicate review.** Compare checksums and, where appropriate, suggest visual duplicates for human review. Never auto-merge based only on similarity.
7. **Human-confirmed metadata.** People, dates, places, and event associations suggested from a Telegram post or image must remain unconfirmed until reviewed.
8. **No public posting by default.** Publishing to the website requires a separate PublicationApproval under the family archive media model.

The first release should support manual upload through the private archive interface. Telegram API-based import is a later, optional capability and must not block that release.

## 7. Browser-based Telegram Web access and media intake

The primary planned access method is the normal Telegram Web user interface in a browser, not a rewrite of the existing bots and not a mandatory Bot API integration.

Canonical entry point: https://web.telegram.org/k/

Expected workflow:
1. Open Telegram Web in a browser profile controlled by the person whose account is being used.
2. The account owner completes Telegram authentication directly in that browser, including password and one-time confirmation code when Telegram requests them.
3. KOMAROVA_CORE may use only the already authenticated browser session and the chats/files that this account is legitimately allowed to access.
4. For `TG-USER-IRINA`, the daughter must herself authorize the intended scope and either perform the export/import herself or explicitly authorize a lawful account/session that already has access. Do not ask her to disclose credentials or transfer her session to another person or service.
5. For `TG-USER-ARTYOM`, apply age-appropriate consent and guardian oversight. Never request or transfer his password, OTP, cookies or session data.
6. For `TG-CHAT-MOTHER`, verify in Telegram Web whether the negative peer ID resolves to a private group, channel or another chat type, and confirm the display identity.
7. An authorized user selects the relevant message, attachment, or explicitly approved batch for intake.
8. The browser workflow downloads the selected photo/video/document without altering the source in Telegram.
9. The downloaded file is copied into the local intake area `KOMAROVA_CORE/intake/telegram/attachments` and handed to File Engine for validation, SHA-256 calculation, duplicate review, provenance capture and MATERIAL-ID registration.
10. Successful intake creates an archive candidate. It does not automatically publish the file to the public website.

Security requirements:
- The owner enters the Telegram password and confirmation code directly into Telegram Web. Never ask the owner to send credentials to ChatGPT or store them in source code, logs, project documentation or ordinary configuration.
- Do not export, copy, print or commit Telegram session cookies, local storage, auth keys or browser profile data.
- Keep the authenticated browser profile local and access-controlled. Do not share it with public hosting or expose it to frontend JavaScript.
- Do not bypass Telegram access controls, CAPTCHA, rate limits, privacy restrictions or technical protections.
- If the session expires or Telegram requests re-authentication, pause and let the owner complete the login interactively.
- Respect Telegram's current terms, account security prompts and the user's actual group membership/permissions.
- Personal-account access requires the account owner's explicit permission for the exact chats, date range and material selected. Permission to view a username or receive a shared file is not blanket permission to archive all private messages.
- For a minor's account, apply age-appropriate consent and guardian oversight.
- A negative numeric peer ID is not enough to identify a mother's personal account; verify its actual peer type and display identity in Telegram Web.

Selection and volume rules:
- The browser method makes downloading possible; it does not mean the entire group history should be downloaded.
- No bulk history download or automatic monitoring is enabled at this stage.
- Support a deliberate user-selected attachment or a user-approved bounded batch, rather than requiring one-at-a-time manual file handling forever.
- Any future rule-based collection of new posts must be separately specified, previewed and approved before activation.
- Preserve exact downloaded bytes; calculate SHA-256; retain chat/message/source references as provenance only.
- Never treat Telegram IDs as PERSON-ID, PHOTO-ID, EVENT-ID or primary archive IDs.
- Intake failures remain visible and retryable; never claim an item was archived before File Engine confirms it.

This browser workflow is a planned capability. It is not yet implemented merely because Telegram Web is accessible in a normal browser.

## 8. Optional API connector boundary

A Telegram API connector may be considered later as a separate optional adapter, but it is not the primary assumption for the current design and is not required for browser-based intake.

The two existing bot sources may be integrated through the Bot API only after their actual deployments, ownership, token custody and update handling are audited. Do not change their code or configuration as part of that audit. The family group can be accessed by a bot only if that bot is already present and its actual privacy mode/permissions allow the required updates; do not change group membership or privacy settings without explicit approval. The daughter's personal user account is not a Bot API source. Any future user-account adapter would require a separate MTProto/user-session design, explicit consent, secure secret handling and a review of Telegram's current terms and restrictions.

Any API capabilities require separate implementation and authorization. Out of scope unless separately approved: full-history scraping, continuous monitoring, sending messages/media, changing bot behavior, automatic public publishing, two-way synchronization, or deletion propagation.

## 9. Security and privacy

- Bot tokens and Telegram API credentials belong only in a server-side secret manager or protected environment configuration.
- Never commit secrets to the repository or expose them in browser JavaScript.
- A group chat ID is an internal connector identifier, not a public access link.
- Enforce authorization in KOMAROVA_CORE before showing imported messages or media.
- Log who initiated an import, which source item was selected, and the resulting archive IDs.
- Provide a clear disconnect/revoke procedure if a connector is added.
- Do not assume that membership in a Telegram group grants permission to access the private KOMAROVA_CORE archive.
- Do not expose group membership, message history, or personal metadata on the public site.

## 10. Acceptance criteria

The link-only website stage is complete when:
1. Both bot links open the correct canonical Telegram usernames.
2. The family group, personal accounts and mother's private chat locator are not exposed publicly.
3. The group is not exposed publicly using the supplied Web Telegram locator.
4. The site does not require Telegram API credentials to render approved links.
5. No existing bot code, deployment, command, or configuration has been changed.
6. No private chat or group media has been downloaded or imported without explicit selection and authorization.
7. No Telegram content is automatically published to the website.

A future connector stage is complete only when explicit selection, authorization, provenance, quarantine, checksum validation, duplicate review, audit logging, and failure handling are tested.
