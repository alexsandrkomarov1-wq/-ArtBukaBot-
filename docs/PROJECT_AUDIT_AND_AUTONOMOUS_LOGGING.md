# KOMAROVA_CORE — аудит и автономный журнал проекта

**Целевая ветка:** \`core-backend-foundation\`  
**Статус:** спецификация и первый PowerShell CLI добавлены; автоматическая интеграция с GitHub, браузером и локальными приложениями ещё не развёрнута.

## 1. Причина предыдущего сбоя

Публичный счётчик активного времени не был измерителем. \`_data/project_time.yml\` содержал фиксированное значение, а \`assets/js/project-time-counter.js\` только отображал его. Журнал \`docs/PROJECT_TIME_LOG.md\` содержал две закрытые сессии общей длительностью 00:02:16. Поэтому календарный возраст обновлялся, а активное время автоматически не собиралось.

Наличие корректно работающего интерфейса не подтверждает полноту исходных данных. Проверка страницы подтвердила отображение значения, но не достоверность полного хронометража.

## 2. Требуемая архитектура

Система состоит из независимых слоёв:

1. **Журнал событий** — append-only JSONL: EVENT-ID, UTC timestamp, локальное время Europe/Amsterdam, источник, тип, описание, привязка к SESSION-ID.
2. **Журнал рабочих сессий** — начало, пауза, продолжение, завершение, категория, задача, длительность.
3. **Восстановление** — незакрытая сессия не закрывается автоматически; неизвестный интервал после аварии не засчитывается.
4. **Источники подтверждений** — GitHub commits/Actions, локальные файлы и журналы, ручные события, переписка. Автоматически обнаруженное событие не приравнивается к активному времени человека.
5. **Панель** — отдельно показывает календарный возраст, подтверждённое активное время, события, открытые/прерванные сессии, источники и ошибки.
6. **Резервирование** — отдельные копии JSONL и состояния с проверкой SHA-256 и тестом восстановления.

## 3. Правила достоверности

- Не выводить рабочие часы из количества сообщений, коммитов, PR или времени выполнения CI.
- Ожидание CI, сборки и сетевых операций записывать как системное время, не как активную работу человека.
- Все отметки хранить в UTC и дополнительно показывать в Europe/Amsterdam.
- Неизвестное время маркировать как неизвестное, а не заполнять оценкой.
- Исправления и уточнения оформлять новыми событиями; исходные строки не перезаписывать.
- Каждая запись должна иметь источник и уровень подтверждения.
- Не считать Google Drive постоянным хранилищем: его OAuth-подключение является временным.
- Не менять \`main\`, production Supabase, базу данных и существующие оригиналы в рамках журнала.

## 4. Первый автономный PowerShell CLI

Файл: \`tools/komarova-core.ps1\`.

Команды:

- \`init\` — создать локальное хранилище журнала;
- \`start -Task ...\` — начать сессию;
- \`pause\`, \`resume\`, \`stop\` — управлять сессией;
- \`recover\` — безопасно приостановить незавершённую сессию без начисления неизвестного времени;
- \`event -Description ...\` — записать событие;
- \`status\` — показать сессию и сумму закрытых интервалов;
- \`ai -Prompt ...\` — обратиться к отдельному ИИ endpoint, совместимому с OpenAI Chat Completions API.

Локальные данные создаются в \`data/project_time/\`:

- \`events.jsonl\` — события;
- \`sessions.jsonl\` — закрытые сессии;
- \`active_session.json\` — текущее состояние.

Скрипт не отправляет журналы в облако, не передаёт семейные материалы ИИ и не сохраняет API-ключи в файлы проекта.

## 5. Независимый ИИ

ИИ-адаптер не зависит от ChatGPT и не содержит ключей OpenAI/ChatGPT. Он обращается к endpoint, задаваемому переменными среды:

- \`KOMAROVA_AI_BASE_URL\`
- \`KOMAROVA_AI_MODEL\`
- \`KOMAROVA_AI_API_KEY\` (необязательно для локального сервера)

Для локального сервера, совместимого с OpenAI API, пример endpoint: \`http://127.0.0.1:11434/v1\` (Ollama). Это только адрес интерфейса, а не утверждение, что Ollama или модель уже установлены. На старом компьютере пользователя совместимость и скорость конкретной модели должны быть проверены до выбора её постоянной.

Ранее существовавший Neon AI Gateway сообщал 0 доступных моделей из 69 и \`paid_plan_required\`; поэтому его нельзя выдавать за бесплатный и готовый inference endpoint. Не использовать платный gateway без отдельного согласия.

Журнал событий и сессий обязан работать без ИИ. ИИ — дополнительный анализатор, а не критическая зависимость и не источник истины.

## 6. Ограничения первой версии

Первая версия CLI регистрирует сессии и события, введённые вручную в PowerShell. Она ещё не собирает автоматически все сообщения ChatGPT, GitHub Actions, активность Windows и события браузера. Для этого нужны отдельные коннекторы с явными правами доступа и тестами.

Первая версия не меняет автоматически публичный счётчик сайта. Сначала необходимо проверить формат журнала, сценарии аварийного восстановления и сверку с реальными источниками. После этого отдельная задача синхронизирует подтверждённые агрегаты с публичной страницей.

## 7. Приёмочные проверки

1. Создать журнал с нуля.
2. Начать сессию, проверить статус.
3. Поставить на паузу, убедиться, что время не растёт.
4. Продолжить и закрыть сессию.
5. Проверить, что закрытая сессия записана ровно один раз.
6. Имитировать прерывание и выполнить recover; неизвестное время не должно попасть в сумму.
7. Добавить событие и проверить UTC/local timestamps.
8. Проверить работу журнала при выключенном ИИ.
9. Подключить отдельный тестовый ИИ endpoint и проверить ответ без передачи файлов и журналов.
10. Создать резервную копию JSONL, сверить SHA-256 и проверить восстановление в отдельную тестовую папку.

**Критерий готовности:** не наличие красивого счётчика, а воспроизводимая проверка, что каждая сумма получена из закрытых записей, а каждая запись имеет проверяемый источник.
