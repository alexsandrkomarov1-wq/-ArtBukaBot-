# KOMAROVA_CORE: облачная репликация

Документ описывает серверную репликацию оригиналов и производных материалов. Он не означает, что облачные аккаунты уже авторизованы или что worker уже размещён на публичном сервере.

## Общие правила

- Первичный объект в таблице stored_blobs остаётся источником истины.
- MATERIAL-ID не меняется при создании облачных копий.
- Каждая копия получает отдельную запись cloud_replicas с именем провайдера, удалённым ID, ожидаемым SHA-256, размером и состоянием.
- Копия получает состояние available только после полного обратного чтения и совпадения размера и SHA-256.
- Ошибка одного провайдера не блокирует обработку очереди другого.
- Оригинал не перезаписывается. Повторная попытка использует стабильный blob ID в имени объекта.
- Секреты и токены хранятся только в переменных окружения/секретах сервера. Не добавлять их в Git.

## Провайдеры

### Microsoft OneDrive

Обязательные серверные переменные:

- ONEDRIVE_SYNC_ENABLED=true
- ONEDRIVE_FOLDER_ID — ID существующей папки KOMAROVA_CORE.
- ONEDRIVE_ACCESS_TOKEN либо пара ONEDRIVE_REFRESH_TOKEN + ONEDRIVE_CLIENT_ID.
- ONEDRIVE_CLIENT_SECRET — если он требуется типом регистрации приложения.
- ONEDRIVE_TENANT_ID — необязательно; по умолчанию consumers.\n- ONEDRIVE_TOKEN_CACHE_FILE — рекомендуется указать путь к защищённому файлу вне репозитория и web-root; обновлённые OAuth refresh/access tokens сохраняются атомарно с ограниченными правами.

Загрузка выполняется через Microsoft Graph upload session фрагментами 10 MiB. После загрузки worker скачивает файл обратно и проверяет SHA-256. Перед передачей проверяется доступная квота OneDrive, если Graph вернул её значение.

### Яндекс Диск

Обязательные переменные:

- YANDEX_DISK_SYNC_ENABLED=true
- YANDEX_DISK_ACCESS_TOKEN — OAuth-токен только на сервере.
- YANDEX_DISK_ROOT=disk:/KOMAROVA_CORE — необязательно; путь по умолчанию.

Яндекс API предоставляет upload URL для передачи файла одним потоковым HTTP PUT, но используемый REST flow не является resumable chunk-session API. Поэтому при сетевом обрыве повторяется передача всего файла; стабильный путь по blob ID предотвращает создание второй копии. Квота проверяется через сведения о диске. После передачи выполняется скачивание и проверка SHA-256.

Для аккаунта без Яндекс 360 справка Яндекса указывает ограничение 1 GB на один файл; для планов Яндекс 360 — до 50 GB. В адаптере безопасный лимит по умолчанию — 1 GiB. Менять его на сервере можно только после проверки реального тарифа аккаунта через YANDEX_DISK_MAX_FILE_BYTES. Справка также описывает месячный лимит загрузки, зависящий от ёмкости диска; текущий worker проверяет свободное место и размер одного файла, но ещё не ведёт точный учёт месячного лимита.

### Google Drive

Существующая очередь google_drive_outbox и worker python -m backend.app.google_drive_sync сохраняются. Используется resumable upload через Google API. Проверочное скачивание выполняется потоково во временный файл, а не в RAM.

Google Drive остаётся временным подключением до отдельного подтверждения постоянного статуса. Не включать GOOGLE_DRIVE_SYNC_ENABLED без решения владельца и валидных серверных OAuth credentials.

## Запуск worker

После применения миграций и настройки серверных секретов:

```powershell
python -m backend.app.migrate
python -m backend.app.cloud_replication
```

Google Drive worker запускается отдельно:

```powershell
python -m backend.app.google_drive_sync
```

Workers должны работать на сервере с постоянным доступом к основной приватной storage и базе данных. Запуск на GitHub Pages невозможен: Pages не исполняет Python workers.

## Состояния реплик

- pending — ожидает передачи.
- uploading — worker взял задачу; lease позволяет восстановиться после остановки процесса.
- available — удалённая копия скачана обратно и проверена.
- retryable_error — временная ошибка, следующая попытка назначена с экспоненциальной задержкой.
- quota_blocked — места недостаточно; автоматические повторы не расходуют запросы.
- failed — исходный blob отсутствует; требуется разбор.

## Ограничения текущего этапа

- Приём файла в текущем FastAPI endpoint пока ограничен 100 MiB. Это не общий объём архива и не предел квоты облака.
- Исходящий OneDrive upload использует фрагменты; Google Drive — resumable upload; Яндекс Disk API в текущем адаптере передаёт поток одним PUT и не умеет продолжать с байтового смещения.
- Worker-код добавлен в репозиторий, но его реальный запуск требует размещённого FastAPI/storage backend, миграции БД и серверных OAuth секретов. GitHub Actions проверяет код, но не выполняет передачу в личные облака.
- Ни одна копия не считается сохранённой до успешной обратной проверки.
